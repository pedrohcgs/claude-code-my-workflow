# Promote repository memory

Treat `MEMORY.md` as the shared, versioned source of durable project learning. Candidate entries come from checkpoints, session logs, or user-nominated repository notes—not private product memory.

For each candidate, evaluate:

- generality across future work;
- evidence from an observed correction or repeated pattern;
- redundancy with `AGENTS.md`, existing skills, guidance, or memory;
- staleness risk;
- whether it is concise and actionable.

When useful, ask independent subagents to score those criteria and synthesize the evidence; reviewer agreement alone is not proof. Promote only with explicit user approval. Use the form `[LEARN:<category>] wrong assumption → reliable approach`, followed by a short “Why” and “How to apply.” Reject transient task state, personal data, secrets, and facts that belong in normal documentation.
